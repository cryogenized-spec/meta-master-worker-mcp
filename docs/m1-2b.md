# M1.2b — GitHub operator verification and MCP consent

**State:** implementation under PR review. No live OAuth app, secrets, KV, Cloudflare deployment or Meta account is configured.

## Intended flow

1. MCP client starts a validated authorization-code + PKCE request to the independent Auth Worker.
2. GET /authorize parses the request, describes the requesting client and creates a browser-bound consent handle using Cloudflare OAuth helpers.
3. The form displays client name, domain, redirect destination and the read-only scope, with client-provided HTML escaped.
4. POST /authorize Deny uses the OAuth helper's validated denial redirect. Allow accepts only mcp:read and starts upstream sign-in only after validating browser-bound consent.
5. GitHub OAuth web flow runs with a fresh PKCE S256 verifier and exact callback URL. No GitHub API scopes are requested.
6. GET /oauth/github/callback validates the upstream state and browser binding, exchanges GitHub's code for a transient token and retrieves the numeric user ID.
7. Only the exact configured operator ID completes MCP authorization for mcp:read. The GitHub token is discarded, never stored as MCP props.
8. The MCP resource Worker independently validates resource-bound bearer tokens and scopes on every tool call.

This authorizes **MCP clients**, not Meta accounts.

## Private configuration contract

- AUTH_ENABLED=true: explicit deploy-time enablement.
- OAUTH_KV: Workers OAuth Provider's KV namespace binding.
- ISSUER: HTTPS issuer URL with trailing slash, such as https://auth.example.org/.
- MCP_SERVER_URL: exact canonical protected resource URL ending /mcp.
- GITHUB_CLIENT_ID: GitHub OAuth application's client ID.
- GITHUB_CLIENT_SECRET: private Cloudflare Worker secret, never a repo variable.
- OPERATOR_GITHUB_USER_ID: numeric stable user ID of the single permitted operator.

GitHub OAuth application callback must be exactly ISSUER + oauth/github/callback. These values have not been configured and no Worker has been deployed.

## Security decisions

- Operator identity verified using GitHub's stable numeric ID, not the mutable login name.
- A posted form cannot supply its own operator ID, trusted redirect target, or unrestricted permissions.
- Consent comes before upstream sign-in; Cloudflare's browser-bound helpers manage handles and state.
- Approval is not remembered automatically. Deny is always supported.
- The only grant is mcp:read. No publishing, messaging, deletion or advertising tools.
- GitHub access token is used only for identity lookup and never persisted, logged or forwarded to MCP clients.
- Production verification must test state replay, CSRF, consent flow, resource audience, revocation, scope denial, expiry, and both Workers against live bindings.

## Remaining prerequisites

Provision and validate private KV and Worker service bindings, register a GitHub OAuth app and secrets, run complete local OAuth integration tests, verify real browser consent, then authorise deployment. Meta account connection and D1 token storage remain separate outstanding tasks.
