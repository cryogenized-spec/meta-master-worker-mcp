# M1.3 — Read-only Meta Graph API foundation

**Status:** internal Graph API and Page-discovery code only. No Meta account, application, token, OAuth grant or Cloudflare deployment has been configured.

## Chosen API version

Graph API **v27.0**, verified from Meta's versioning documentation in November 2026.

Sources:
- https://developers.facebook.com/docs/graph-api/guides/versioning
- https://developers.facebook.com/docs/graph-api/overview
- https://developers.facebook.com/docs/graph-api/guides/secure-requests
- https://developers.facebook.com/docs/graph-api/reference/page/

Before production onboarding, revisit Meta's permissions and API version changelog. A locally successful mock is not evidence of a real Page grant.

## Implemented (not exposed as MCP tools)

### Read-only Graph client

- Fixed HTTPS graph.facebook.com host and explicit v27.0 path.
- One allowlisted read endpoint: GET /v27.0/me/accounts with only id, name, tasks and up to 25 results.
- No arbitrary URL or endpoint supplied by the model. No POST, DELETE, update or publish operation.
- Credentials sent via Bearer authorization header, never placed in an access_token URL parameter.
- Optionally computes Meta's HMAC-SHA256 appsecret_proof from a server-side app secret.
- Bound response-size limit and strict shape validation; never return unexpected access_token fields from provider responses.
- Cursors, not full provider-supplied paging.next URLs, are used for further pages; never follow a dynamic next URL.
- Bounded retries for read-only transient/rate-limit failures. No retry on permission or invalid-token failures.
- Error categories contain no raw provider messages, headers, trace IDs, access tokens or transport URLs.

### Operator-scoped Page discovery

- List only through a connection belonging to the verified operator identity.
- Require the exact pages_show_list grant before decrypting any stored token.
- Fail closed for unknown/foreign/non-Facebook connections and expired credentials.
- Never expose plaintext access tokens or encrypted token fields in the returned Page list.
- This service remains internal until live OAuth and scope/ownership checks are exercised through a deployed resource Worker.

## Pending before a real Page can be listed

1. Register and verify GitHub OAuth operator login with an actual test browser.
2. Provision Cloudflare OAuth KV, D1 and private secrets; link the two Workers via service binding.
3. Register a Meta developer app and perform official Meta login for an eligible operator-managed Page.
4. Inspect granted scopes, connected assets and Page tasks. Check whether pages_show_list, business_management or other permissions are required for the actual account.
5. Safely persist the User token via the encrypted vault and verify its expiry, refresh and revocation.
6. Verify the Graph API response using live authorized test assets; account for platform restrictions and permission review.
7. Only then expose a read-only MCP tool, with operator identity derived exclusively from an authenticated MCP context.

## Non-goals

Personal profile scraping, unrestricted Graph API proxies, customer messaging, Page publishing and advertising changes are excluded. They must not be enabled through this module.

## Running tests

The existing npm run check command runs TypeScript, unit tests and local workerd OAuth/D1 integration tests. npm run build dry-runs both Workers. Neither uses live Meta credentials.
